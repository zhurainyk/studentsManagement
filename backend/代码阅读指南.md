# 学生管理系统 · Java 后端代码阅读指南（零基础版）

> **面向**：没写过 Java 后端，但看得懂前端 JS / Vue 的同学。
> **读完你能回答**：一个请求从浏览器出发、到数据库、再回到页面，中间经过了谁？每一层为什么必须存在？每个文件在干什么？
> **与 `backend/README.md` 的分工**：README 讲「怎么跑起来、怎么调接口」，本文件讲「怎么读代码、为什么这样设计」。

---

## 0. 先建立整体印象：这个项目在做什么

一句话：**前端是「点单界面」，后端是「服务员 + 厨房 + 仓库」，数据库是「仓库里的货架」**。

- 你在页面上点「添加学生」→ 浏览器发出一个 HTTP 请求（相当于递一张单子）。
- 后端收到单子 → 检查格式对不对 → 把数据存进数据库 → 回一张「回执」。
- 前端拿到回执 → 刷新表格。

整个后端只做一件事：**把 4 个 HTTP 接口，翻译成对一张 `students` 表的增删改查（CRUD）**。

| 前端动作 | HTTP 请求 | 后端做的事 |
|---|---|---|
| 打开页面 / 搜索 / 翻页 | `GET /api/students?page=1&pageSize=10&keyword=张` | 查数据库，返回「当前页数据 + 总条数」 |
| 点「添加」 | `POST /api/students` + JSON | 校验参数，插入一行，返回新学生（含自动生成的 id） |
| 点「编辑」 | `PUT /api/students/1` + JSON | 校验参数，确认存在，更新一行 |
| 点「删除」 | `DELETE /api/students/1` | 删除一行，删不到就报「学生不存在」 |

**所以你读代码时永远抓住一条主线：数据从 HTTP 进来 → 一层层变形 → 变成 SQL → 结果再一层层变回 JSON。** 后面第 5 节会把这条线一步步走一遍。

## 1. 读代码前先补 7 个概念（都用本项目举例）

### 1.1 HTTP：方法 + 地址 + 请求体 + 响应体

浏览器和后端之间靠「文本」通信。一个请求包含：

- **方法（verb）**：`GET` 查、`POST` 增、`PUT` 改、`DELETE` 删。
- **路径（URL）**：`/api/students/1`。
- **查询参数**：`?page=1&pageSize=10`（GET 常用，跟在 `?` 后面）。
- **请求体（body）**：一段 JSON 字符串，如 `{"name":"张三","age":20,...}`（POST/PUT 用）。
- **响应体**：后端返回的 JSON。

本项目所有响应长这样（**这是前后端的「契约」，务必先记住**）：

```json
{ "code": 200, "message": "success", "data": { "list": [], "total": 10, "page": 1, "pageSize": 10 } }
```

`code` 是**业务状态码**：200 成功、400 参数错、404 学生不存在、500 服务器错。注意它和 HTTP 状态码是两回事，见 6.5 节。

### 1.2 JSON ↔ Java 对象（Jackson）

前端发的是 JSON 文本，Java 里用的是对象。Spring Boot 内置 **Jackson**，自动做两件事：

- 进来：`{"name":"张三"}` → 自动 `new StudentRequest()` 并调用 `setName("张三")`（靠 `@RequestBody`）。
- 出去：`Result` 对象 → 自动变成 `{"code":200,...}`（靠 `@RestController`）。

**所以你会看到代码里没有任何一行手写 JSON 解析**，全是框架做的。这也是零基础最容易困惑的点：「我明明没写转换代码啊？」——是注解帮你在进门/出门时做了。

### 1.3 数据库、表、SQL

数据在 `students` 表里，5 列：`id / name / age / class_name / phone`。
后端不「操作文件」，而是发 **SQL 语句**给数据库执行：

```sql
SELECT id, name, age, class_name, phone FROM students WHERE name LIKE '%张%' LIMIT 10 OFFSET 0;
```

`class_name`（数据库列名，下划线风格）和 `className`（Java / 前端字段名，驼峰风格）的自动对应，靠 `application.yml` 里的 `map-underscore-to-camel-case: true`。

### 1.4 Maven 与 `pom.xml`

Java 项目不像前端用 `package.json` + `npm install`，而是用 **`pom.xml` + Maven**：声明依赖坐标（谁家的哪个库、哪个版本），Maven 自动下载。

本项目 `pom.xml` 只引了 5 个依赖，第 2.3 节有对照表。**`pom.xml` 是你要读的第一个文件之一**，因为它告诉你「这个后端用了哪些技术」。

### 1.5 Spring 的容器 / Bean / 依赖注入（★ 最重要，零基础最容易卡住）

你会在代码里发现一件诡异的事：**全项目没有任何一行 `new StudentController()`、`new StudentServiceImpl()`、`new StudentMapper()`，但它们却能被正常调用。**

原因是 Spring 有一个「容器」（可以理解为一个大对象仓库）：

1. 程序启动时，Spring 扫描 `com.example.students` 包，看到带 `@RestController`、`@Service`、`@Configuration` 的类，就各自 `new` 一个实例，放进容器。这些实例叫 **Bean**。
2. `StudentController` 的构造器声明「我要一个 `StudentService`」，Spring 就从容器里找到唯一的实现 `StudentServiceImpl`，自动塞进去。
3. 而创建 `StudentServiceImpl` 时又需要 `StudentMapper`，容器里恰好也有（由 MyBatis 生成的代理对象，见 1.6）。
4. 于是三层对象像搭积木一样自动串好了。

这叫 **依赖注入（DI）** / **控制反转（IoC）**。代码里表现就是「构造器参数」：

```java
public StudentController(StudentService studentService) {  // Spring 自动传进来
    this.studentService = studentService;
}
```

**读代码时看到构造器参数，就在心里想：这是 Spring 从容器里递过来的，不是我手动 new 的。**

### 1.6 MyBatis 的「接口 → 代理对象 → XML SQL」

`StudentMapper` 是一个**只有方法名、没有方法体**的接口：

```java
List<Student> selectByPage(StudentQuery query);
```

Java 接口本来不能被调用，但启动类上的 `@MapperScan` 让 MyBatis 在运行时**动态生成一个实现类（代理对象）**。它怎么知道每个方法该执行哪条 SQL？靠 `resources/mapper/StudentMapper.xml`：

- `namespace` = 接口的完整包名（`com.example.students.mapper.StudentMapper`）→ 绑定哪个接口
- `<select id="selectByPage">` 的 `id` = 方法名 → 绑定哪个方法

调用 `studentMapper.selectByPage(query)` 时，实际上是：代理对象 → 找到同名 XML 片段 → 拼好 SQL → 交给 JDBC 执行 → 把结果行转成 `Student` 对象列表返回。

### 1.7 分层架构：为什么不能一个文件写完

技术上完全可以写一个文件搞定 4 个接口，但项目被拆成 5 层，是为了**让每一层只关心一件事**：

| 层 | 关心什么 | 不关心什么 |
|---|---|---|
| Controller | HTTP：地址、参数、返回 JSON | 数据怎么存、业务规则 |
| Service | 业务规则：分页规整、存在性判断、事务 | HTTP、SQL 怎么写 |
| Mapper | SQL 怎么执行 | 业务含义 |
| DTO / Entity | 数据长什么样 | 逻辑 |
| common / config | 横切能力：统一响应、异常、跨域 | 具体业务 |

好处：改「每页最多 100 条」只动 Service；改「按班级搜索」只动 XML；改「返回格式」只动 `Result`。**分层的本质是「隔离变化」**。

### 2.3 技术栈对照表（读 `pom.xml` 时对照）

| pom.xml 依赖 | 作用 | 代码里在哪里体现 |
|---|---|---|
| `spring-boot-starter-web` | 内嵌 Tomcat、Spring MVC、Jackson | `@RestController`、`@GetMapping`、自动 JSON 转换 |
| `mybatis-spring-boot-starter` | 把接口和 XML SQL 绑定 | `@MapperScan`、`StudentMapper`、`StudentMapper.xml` |

`<parent>` 是 Spring Boot 2.7.18：它统一管理了几百个库的版本号，所以上面的依赖大多不用写 `<version>`。`java.version=8` 表示按 Java 8 语法编译。

## 3. 阅读路线：从哪里入手（★ 核心答案）

**原则：先看「契约」和「入口」，再沿着一条请求走主干，最后补横切配件。不要按文件夹字母顺序从 `common` 开始读**——那些类脱离了使用场景会看不懂为什么存在。

| 站 | 目标 | 依次打开 | 读完应能回答 |
|---|---|---|---|
| 0 | 建立直觉 | `README.md` → 启动一次 → `curl` 打一次接口 → 打开 H2 console 看表 | 系统对外表现是什么？返回的 JSON 长什么样？ |
| 1 | 记住契约 | `src/api/student.js`、`src/mock/index.js`、`common/Result.java`、`common/PageResult.java` | 前端发什么、期望收到什么？后端为什么必须长成这个形状？ |
| 2 | 找到入口 | `pom.xml`、`StudentsApplication.java`、`application.yml`、`schema-h2.sql`、`data.sql` | 程序从哪开始？端口/数据库/初始数据从哪来？ |
| 3 | 走主干 | `StudentController` → `StudentService` → `StudentServiceImpl` → `StudentMapper` → `StudentMapper.xml` | 一次查询的数据是怎么一层层变形的？ |
| 4 | 补配件 | `entity/Student.java`、`dto/*`、`common/BusinessException.java`、`common/GlobalExceptionHandler.java`、`config/WebConfig.java` | 参数怎么校验？出错怎么变成统一响应？ |
| 5 | 收尾扩展 | `application-mysql.yml`、`schema-mysql.sql` | 怎么换数据库？怎么用 curl / H2 console 验证自己的改动？ |

### 第 0 站｜先跑起来（很重要，别跳过）

```bash
cd backend
mvn spring-boot:run          # 需要 JDK 8+ 与 Maven
curl 'http://localhost:8081/api/students?page=1&pageSize=10&keyword=张'
```

看着终端返回的真实 JSON，再去看代码，抽象概念立刻就有实物对应。
再打开 `http://localhost:8081/h2-console`（JDBC URL 填 `jdbc:h2:mem:students`，用户 `sa`，密码空），执行 `SELECT * FROM students`，你会看到「数据真的躺在一张表里」。

**建议把 `backend/README.md` 里的 4 个 curl 示例都打一遍**：列表 / 新增 / 编辑 / 删除，再故意删一个不存在的 id 看 `code: 404`、故意传非法参数看 `code: 400`。零基础先看清「请求 → JSON」的真实往返，比一上来啃实现更容易建立全局观。

### 第 1 站｜先锁死「输入输出」

先读前端 `src/api/student.js`（40 行）：`baseURL: '/api'`，4 个函数，以及响应拦截器里 `if (res.code !== 200) return Promise.reject(...)`。
再读 `src/mock/index.js`：这是「假后端」，它返回的 JSON 结构就是**真后端必须一比一复刻的契约**。
最后读 `Result.java` / `PageResult.java`：真后端就是用这两个类把数据装成那个形状。

> 关键认知：这个项目是**先有前端和 Mock，后有 Java 后端**。所以后端很多「奇怪」的设计（比如失败也返回 HTTP 200）都是在迁就既有契约，不是 Java 圈的通用写法。想通这一点，很多疑惑会消失。

### 第 2 站｜找到「程序从哪开始」

`StudentsApplication.main()` 只有一行 `SpringApplication.run(...)`。这一行会：启动内嵌 Tomcat（监听 8081）→ 创建 Spring 容器 → 扫描并注册 Bean → 执行 `schema-h2.sql` 建表 → 执行 `data.sql` 插 10 条数据 → 就绪。
然后读 `application.yml`，把每个配置块和上面的动作对上号（端口、数据源、SQL 初始化、H2 控制台、MyBatis XML 路径、驼峰映射）。

### 第 3 站｜沿一条请求走主干（第 5 节会逐步展开）

从 `StudentController.list()` 开始，**每看到一个方法调用就跳到对应文件**，走完 5 个文件再回来。不要跳读，不要在单个文件里深挖工具类细节。

### 第 4 站｜补横切配件

此时你再看 `StudentRequest` 的校验注解、`GlobalExceptionHandler` 的 5 个 `@ExceptionHandler`，就能明白它们是在「请求进 Controller 之前」和「异常抛出之后」两个时机插进来的。

### 第 5 站｜验证与扩展

按第 9 节的实验清单动手改代码，每次改完用 `curl` 重新打一遍相关接口，对照第 5 节的链路图确认数据在哪一层变了形；最后再尝试切换到 MySQL profile。

## 4. 逐文件详解

### 4.1 入口与配置

#### `pom.xml`
**作用**：项目说明书 + 依赖清单。坐标 `com.example:students-backend:1.0.0`。
**为什么先读**：它限定了技术边界——看到 `mybatis-spring-boot-starter` 就知道 SQL 写在 XML 里，看到 `h2` 就知道不用装数据库。
**易踩点**：`spring-boot-starter-*` 是「启动器」，一个依赖会连带拉进一大包相关库，所以文件里只有 5 个 `<dependency>` 却能跑起整个 Web 服务。

#### `StudentsApplication.java`（20 行）
**作用**：唯一入口。
- `@SpringBootApplication`：三合一注解 = 配置类 + 开启自动配置 + **扫描当前包及子包**下的组件。这就是 `@RestController` / `@Service` / `@Configuration` 能被发现的原因（也解释了为什么所有类都必须放在 `com.example.students` 下面）。
- `@MapperScan("com.example.students.mapper")`：告诉 MyBatis 去扫描 `mapper` 包，为接口生成代理实现并注册成 Bean。所以 `StudentMapper` 上不需要再写 `@Mapper`。
- `main()`：`SpringApplication.run(...)` 启动整个应用，**进程不退出**，因为 Tomcat 在监听端口。

#### `resources/application.yml`
**作用**：所有「不改代码就能改行为」的开关，启动时被 Spring 读取。
逐块解释：

| 配置 | 含义 |
|---|---|
| `server.port: 8081` | 后端端口；前端是 8080，两者不同 |
| `spring.datasource.url: jdbc:h2:mem:students...` | **内存数据库**：数据在进程内存里，`MODE=MySQL` 让 SQL 语法贴近 MySQL，`DB_CLOSE_DELAY=-1` 保证连接关了库还在 |
| `spring.sql.init.mode: always` + `schema-locations` + `data-locations` | 每次启动都自动执行建表脚本和数据脚本 → 所以「重启后数据恢复成初始 10 条」 |
| `spring.h2.console.enabled: true` | 浏览器可视化查看表的调试工具 |
| `mybatis.mapper-locations: classpath:mapper/*.xml` | 告诉 MyBatis 去哪读 SQL 文件 |
| `mybatis.configuration.map-underscore-to-camel-case: true` | `class_name` ↔ `className` 自动映射（★ 项目里最经典的坑） |

#### `resources/application-mysql.yml`
**作用**：可选的「配置档（profile）」。文件名 `application-{名字}.yml` 是 Spring 的约定，用 `-Dspring-boot.run.profiles=mysql` 激活后会**叠加/覆盖**主配置。
关键差异：`spring.sql.init.mode: never` —— 真数据库不能每次重启都重建表和插数据，初始化需手工执行一次。
**设计点**：把环境差异放在配置文件里，Java 代码一行都不用改。

#### `resources/schema-h2.sql` / `schema-mysql.sql` / `data.sql`
**作用**：DDL（建表）+ 初始数据。
- 两个建表脚本字段完全一样，只有自增主键写法不同：H2 用 `GENERATED BY DEFAULT AS IDENTITY`，MySQL 用 `AUTO_INCREMENT`（外加 `ENGINE=InnoDB`、字符集）。这就是「数据库方言差异」。
- `data.sql` 的 10 条数据与 `src/mock/data.js` 一致；**故意不写 id**，交给数据库自增，避免和自增序列打架。
- 表结构里 `NOT NULL` 是数据库层的最后一道防线，和业务校验（第 4.4 节）是两道独立的关卡。

### 4.2 主干四层

#### `controller/StudentController.java`（60 行）
**作用**：HTTP 层的「接线员」，把 4 个 URL 映射到 4 个 Service 方法。逐行要点：

- `@RestController` = `@Controller` + `@ResponseBody`，含义是「这个类的方法返回值直接序列化成 JSON，不当作页面名」。
- `@RequestMapping("/api/students")` 类级别公共前缀；方法上的 `@GetMapping` / `@PostMapping` / `@PutMapping("/{id}")` / `@DeleteMapping("/{id}")` 决定「哪个 URL + 哪个 HTTP 方法」进哪个方法。
- `list(StudentQuery query)` **没有写任何注解**：Spring 会把 `?page=1&pageSize=10&keyword=张` 按名字自动填进 `StudentQuery` 的同名属性（这叫参数绑定）。
- `@RequestBody`：把请求体 JSON 转成 `StudentRequest` 对象。
- `@PathVariable Long id`：把 `/api/students/1` 里的 `1` 取出来。
- `@Valid`：触发 `StudentRequest` 上的校验规则，失败会抛异常（不进方法体）。
- 构造器注入 `StudentService`：Spring 自动传入实现类（见 1.5）。
- 每个方法都用 `Result.success(...)` 包一层，返回类型写成 `Result<PageResult<Student>>`、`Result<Student>`、`Result<Void>` 这种嵌套泛型，表达的正是最终 JSON 的形状。

**为什么这一层这么薄**：Controller 里没有任何业务判断。好处是业务规则集中在一处，将来加个 App 端或改 URL 都不影响业务逻辑。

#### `service/StudentService.java`（20 行）
**作用**：接口，只列「能做哪 4 件事」，不写实现。
**为什么要多一个接口**：Controller 依赖的是「抽象」而不是「具体类」。将来想把实现换成缓存版、Mock 版，Controller 一行不用改。这是 Java 后端的常见习惯（本项目只有一个实现，主要起教学示范作用）。

#### `service/impl/StudentServiceImpl.java`（90 行，★ 业务核心，建议精读）
**作用**：所有业务规则 + 事务边界。逐个方法拆：

- `@Service`：标记为 Bean，交给容器管理。
- `list()`（第 28–49 行）三步：
  1. **规整分页**：`page` 为空或 <1 时强制为 1；`pageSize` 为空/<1 时为 10，且用 `Math.min(..., MAX_PAGE_SIZE=100)` 封顶，防止有人传 `pageSize=9999999` 把整表拉爆。
  2. **清洗 keyword**：`trim()`，空串转成 `null`（这样 XML 里的 `<if>` 就不会拼出 `LIKE '%%'`）。
  3. **算 offset 并查两次库**：`(page - 1) * pageSize` 是「跳过多少行」；先 `selectByPage` 拿当前页，再 `countByKeyword` 拿符合条件的**总条数**（分页组件要显示"共 N 条"，必须单独 COUNT），最后打包成 `PageResult`。
- `add()`（第 52–59 行）：`copyFields` 把请求对象的 4 个字段复制到实体 → `insert` → **直接返回这个实体**。之所以它有 id，是 XML 里 `useGeneratedKeys="true" keyProperty="id"` 把数据库生成的自增主键回填到了 `student.id`。
- `update()`（第 62–73 行）：先 `selectById` 确认存在，不存在就 `throw new BusinessException(404, "学生不存在")`；更新完再查一次返回「库里的最新对象」，与 Mock 的 `{...old, ...new}` 行为对齐。
- `delete()`（第 76–82 行）：**不先查**，直接删，用「受影响行数 `== 0`」判断是否不存在，少一次数据库往返。
- `copyFields()`：一个私有小方法，避免 add/update 重复写 4 行 set。
- `@Transactional`：加在三个写方法上，表示「方法内所有数据库操作在同一事务里，出错整体回滚」。**诚实说明**：本项目每个写方法只有一条 SQL，事务效果看不出来；它是示范「写操作应该划在事务边界内」，真实项目里多步写（如"删学生 + 写日志 + 更新班级人数"）才体现价值。
- 第 34 行注释承认：**没有对 LIKE 的 `%` `_` 通配符做转义**，所以搜 `%` 会匹配全部。这是留给你的进阶思考题，不是 bug 遗漏的巧合。

#### `mapper/StudentMapper.java`（26 行）
**作用**：持久层接口，声明 6 个数据操作，无实现体。
- `selectByPage` / `countByKeyword` 收 `StudentQuery`，XML 里直接读它的 `pageSize`、`offset`、`keyword` 属性。
- `selectById(@Param("id") Long id)` / `deleteById(@Param("id") Long id)`：`@Param("id")` 给参数起名，XML 里才能用 `#{id}` 取到。（单参数时其实可省略，这里显式写出是为了教学清晰。）
- `insert` / `update` 收 `Student`，XML 里用 `#{name}`、`#{className}` 直接读属性。
- 返回 `int` 的 `update` / `deleteById` 是 **受影响行数**，这正是 `delete()` 判断 404 的依据。

#### `resources/mapper/StudentMapper.xml`（58 行，★ 数据落地处）
**作用**：6 条手写 SQL。逐块解释：

- `namespace="com.example.students.mapper.StudentMapper"`：必须与接口全限定名一致，这是绑定关系的第一半；每个标签的 `id` 必须等于方法名，是第二半。
- `<sql id="keywordWhere">` + `<where>` + `<if>`：**动态 SQL**。`<include refid="keywordWhere"/>` 把条件片段复用在列表查询和 COUNT 查询中，保证「数据」和「总数」的筛选条件永远一致（这是分页最容易写错的地方）。`<where>` 会自动去掉开头多余的 `AND`，keyword 为空时整个 WHERE 都不生成。
- `LIMIT #{pageSize} OFFSET #{offset}`：MySQL / H2 的分页写法。
- `#{...}`：**预编译占位符**，最终变成 JDBC 的 `PreparedStatement` 里的 `?`，参数不会被当成 SQL 拼接 → 天然防 SQL 注入。（对比 `${}` 是字符串直接拼接，不安全，本项目没用。）
- `resultType="com.example.students.entity.Student"`：查出的每一行自动 new 一个 `Student`，按列名 ↔ 属性名赋值；`class_name → className` 靠主配置里的驼峰映射。
- `useGeneratedKeys="true" keyProperty="id"`：插入后把数据库生成的自增 id 写回入参对象的 `id` 属性——这是 `add()` 能返回带 id 对象的全部秘密。
- `<update>` / `<delete>` 里 `WHERE id = #{id}` 千万别漏，否则会改/删全表。

### 4.3 数据对象（Entity 与 DTO）

> **为什么有三份"长得差不多"的类？** 因为它们服务于不同场景，字段和规则不同。这是后端最常见的设计之一。

| 类 | 使用场景 | 字段 | 特别之处 |
|---|---|---|---|
| `entity/Student.java` | 对应数据库一行；作为返回数据 | id, name, age, className, phone | 有 id；无校验注解 |
| `dto/StudentRequest.java` | POST/PUT 请求体 | name, age, className, phone | **故意没有 id**；带 6 个校验注解 |
| `dto/StudentQuery.java` | GET 查询参数 | page, pageSize, keyword, offset | `page=1`/`pageSize=10` 有默认值；`offset` 是 Service 算出来**回写**的派生字段，不来自 URL |

#### `entity/Student.java`
纯 POJO（只有私有字段 + getter/setter）。它同时扮演两个角色：**MyBatis 的查询结果载体** 和 **Jackson 的响应序列化来源**。`Long id` 用包装类型而非 `long`，因为新增前 id 是 `null`。

#### `dto/StudentRequest.java`
- `@JsonIgnoreProperties(ignoreUnknown = true)`：前端编辑时会把 `id` 也放进 JSON，但这个类没有 id 字段；加了这个注解，多余字段被安静忽略，不会报「无法识别的字段」错误。**编辑以 URL 路径上的 id 为准**，防止请求体伪造 id 改到别人。
- 校验注解与 `StudentForm.vue` 的 `rules` 一一对应：

| 注解 | 含义 | 前端对应 |
|---|---|---|
| `@NotBlank` | 非 null、非空串、非纯空格 | `required: true` |
| `@Size(min=2,max=20)` | 长度 | `min/max` |
| `@NotNull` + `@Min(1)` + `@Max(150)` | 年龄范围 | `el-input-number` 的 min/max |
| `@Pattern(regexp="^1[3-9]\\d{9}$")` | 手机号正则 | `pattern: /^1[3-9]\d{9}$/` |

> **重要观念**：前端校验只是为了「体验」（即时提示），**后端校验才是「安全边界」**。别人可以用 curl 绕过页面直接打接口，所以后端必须独立再校验一遍。

#### `dto/StudentQuery.java`
`Integer`（可为 null）而非 `int`，是为了能区分「没传」和「传了 0」。`offset` 与 URL 无关，是 Service 计算后塞回去给 XML 用的，属于「把对象当数据袋子在层间传递」的用法。

### 4.4 横切四件套

#### `common/Result.java`
**作用**：统一响应外壳，`{code, message, data}`。
- 泛型 `T` 让 `data` 可以是任意类型：`Result<Student>`、`Result<PageResult<Student>>`、`Result<Void>`（data 为 null）。
- 静态工厂 `success(data)` / `success(message, data)` / `fail(code, message)` 让 Controller 一行搞定，不用到处 `new` + `set`。
- 常量 `SUCCESS/BAD_REQUEST/NOT_FOUND/ERROR` 避免魔法数字散落。
- 类注释点明了最关键的设计约束：**业务失败也返回 HTTP 200，只在 `body.code` 里表达失败**，因为前端拦截器只读 `code`。

#### `common/PageResult.java`
**作用**：分页数据 `{list, total, page, pageSize}`，字段名与 `StudentList.vue` 里 `res.data.list` / `res.data.total` 严格对齐。`total` 用 `long` 是因为 `COUNT(*)` 可能超过 int 范围。

#### `common/BusinessException.java`
**作用**：自定义运行时异常，比 `RuntimeException` 多带一个 `int code`。
Service 里 `throw new BusinessException(Result.NOT_FOUND, "学生不存在")` —— 业务层只管「抛出问题」，完全不用知道 HTTP 和 JSON 长什么样，这是分层解耦的体现。

#### `common/GlobalExceptionHandler.java`（55 行）
**作用**：全局异常兜底，把任何地方抛出的异常统一转成 `Result.fail(...)`。
- `@RestControllerAdvice`：一个覆盖所有 Controller 的「切面」，异常从任何一层冒出来都会被它接住。
- 5 个 `@ExceptionHandler`，Spring 按「异常类型最匹配」选择：

| 处理的方法 | 触发场景 | 返回 |
|---|---|---|
| `handleBusinessException` | Service 主动抛「学生不存在」 | code 404 + 原消息 |
| `handleValidationException` | `@Valid` 校验失败 | code 400 + 所有字段错误用「；」拼起来 |
| `handleNotReadableException` | 请求体不是合法 JSON | code 400 + 提示 |
| `handleTypeMismatchException` | `/api/students/abc`（id 不是数字） | code 400 + 提示 |
| `handleException` | 兜底，任何没预料到的异常 | code 500 + 打日志 |

- **设计要点**：兜底方法 `log.error` 把堆栈留在服务端，只给前端一句通用话术，不暴露内部实现；前 4 个具体异常则不打日志（属于可预期的用户输入错误）。
- **替代了什么**：没有它，每个 Controller 方法都要写 `try/catch`，代码会重复 4 遍。

#### `config/WebConfig.java`
**作用**：CORS 跨域放行。
- `@Configuration` + 实现 `WebMvcConfigurer` → 覆盖 `addCorsMappings` 来定制 MVC 行为。
- 只对 `/api/**` 放行 `localhost:8080`，允许 4 种方法 + 预检 `OPTIONS`。
- **本项目默认用不到它**：`vue.config.js` 的 `devServer.proxy` 把 `/api` 转发到 8081，浏览器自始至终只跟 8080 通信，属于同源请求，没有跨域问题。只有当你把 `src/api/student.js` 的 `baseURL` 改成 `http://localhost:8081/api` 直连时，才需要这份配置。

## 5. 三条完整链路（把散落的文件串起来）

### 5.1 主链路：搜索「张」并翻到第 2 页

请求：`GET http://localhost:8080/api/students?page=2&pageSize=5&keyword=张`

| # | 位置 | 发生了什么 | 数据形态 |
|---|---|---|---|
| 1 | `StudentList.vue` | `created()` → `fetchData()` → `getStudents({page,pageSize,keyword})` | JS 对象 |
| 2 | `src/api/student.js` | axios 发 `GET /api/students?...`（`baseURL: '/api'`） | HTTP 请求 |
| 3 | `vue.config.js` | devServer 代理把 `/api` 转发到 `http://localhost:8081` | 同一个请求换个目的地 |
| 4 | 内嵌 Tomcat / DispatcherServlet | 按 `GET + /api/students` 找到 `StudentController.list()` | 路由匹配 |
| 5 | `StudentController.list` | 参数绑定：`?page=2&pageSize=5&keyword=张` → `StudentQuery` 三个属性 | `StudentQuery{page=2,pageSize=5,keyword="张",offset=0}` |
| 6 | `StudentServiceImpl.list` | 规整：page=2、pageSize=5；keyword trim 后仍为「张」；`offset=(2-1)*5=5` 回写对象 | `StudentQuery{..., offset=5}` |
| 7 | `StudentMapper.selectByPage` | MyBatis 代理对象按 `namespace + id` 找到 XML 片段 | 接口调用 |
| 8 | `StudentMapper.xml` | `<if>` 成立 → 拼出 `... WHERE name LIKE CONCAT('%',?,'%') ORDER BY id LIMIT ? OFFSET ?`，`#{ }` 变成预编译 `?` | 参数化 SQL |
| 9 | H2 | 执行，返回若干行 | 结果集 |
| 10 | MyBatis | 每行 → `Student` 对象；`class_name` 列 → `className` 属性（驼峰映射） | `List<Student>` |
| 11 | `countByKeyword` | 复用同一 `<include>` 条件，`SELECT COUNT(*)` → 总条数 | `long total` |
| 12 | `StudentServiceImpl` | `new PageResult<>(list, total, 2, 5)` | `PageResult` |
| 13 | `StudentController` | `Result.success(pageResult)` → 泛型嵌套 | `Result<PageResult<Student>>` |
| 14 | Jackson | 对象序列化为 JSON | `{"code":200,"message":"success","data":{...}}` |
| 15 | axios 响应拦截器 | `res.code === 200` → 原样 `return res` | JS 对象 |
| 16 | `StudentList.vue` | `tableData = res.data.list`、`total = res.data.total` → 表格/分页渲染 | 页面 |

**一句话记忆**：URL 参数 → Query 对象 → 补 offset → 动态 SQL → 行转对象 → 装 PageResult → 装 Result → JSON → 页面。

### 5.2 新增链路（多了「校验」和「自增 id 回填」）

`POST /api/students` + `{"name":"新同学",...}`

1. Jackson 把 JSON 转成 `StudentRequest`；`@JsonIgnoreProperties` 静默忽略多余字段。
2. `@Valid` 逐条校验注解。**如果失败**：抛 `MethodArgumentNotValidException` → 方法体根本不执行 → `GlobalExceptionHandler.handleValidationException` 收集所有字段错误 → 返回 `{"code":400,"message":"姓名长度在2到20个字符；请输入正确的手机号"}` → 前端拦截器 `Promise.reject` → 弹「操作失败」。
3. 校验通过进 Controller → `StudentServiceImpl.add()`（`@Transactional` 开启事务）。
4. `copyFields` → `StudentMapper.insert` → XML 的 `INSERT` 执行，`useGeneratedKeys` 把新 id 回填到 `student.id`。
5. 返回该对象 → `Result.success("添加成功", student)` → JSON 里带上 id → 提交事务。

### 5.3 异常链路（理解「抛出去就有人接」）

`DELETE /api/students/9999`

1. Controller → `StudentServiceImpl.delete(9999)` → `studentMapper.deleteById` 返回 `0`（没有行被删）。
2. `throw new BusinessException(404, "学生不存在")`。
3. 异常**一路向上冒泡**，Service 和 Controller 都没有 try/catch。
4. 被 `@RestControllerAdvice` 的 `handleBusinessException` 接住 → `Result.fail(404, "学生不存在")`。
5. HTTP 状态仍是 **200**，body 是 `{"code":404,"message":"学生不存在","data":null}`。
6. axios 拦截器看到 `code !== 200` → `Promise.reject(new Error("学生不存在"))` → 页面 `catch` 弹「删除失败」。

> 这条链路是理解「横切层」的最好例子：Service 只负责喊「出错了」，具体怎么变成 JSON 完全由别的类负责。

## 6. 架构设计拆解（为什么这么设计）

### 6.1 依赖方向是单向的

```
Controller ──依赖──► Service(接口) ◄──实现── ServiceImpl ──依赖──► Mapper ──► 数据库
```

Controller 只认识 `StudentService` 接口，不认识 `StudentServiceImpl`；ServiceImpl 只认识 `StudentMapper` 接口，不认识 XML 细节。**每层只依赖下一层的抽象**，所以替换任意一层的实现，上层无感。

### 6.2 对象在层间「变形」，而不是一个类从头传到尾

```
JSON 文本  →  StudentRequest(入参 DTO)  →  Student(实体)  →  SQL 行
SQL 行     →  Student(实体)  →  PageResult  →  Result  →  JSON 文本
```

`StudentRequest` 故意不含 id（防止伪造），`StudentQuery` 故意含 offset（计算产物），`Student` 才是表里一行的完整映射。**入参、出参、库表三者分开**，是真实项目的基本功；小项目合并成一个类也能跑，但一旦加「密码不能返回给前端」「创建时间不让用户传」这类需求就会失控。

### 6.3 统一响应 + 全局异常 = 全系统只有一种「说话方式」

`Result` 定义「成功长什么样」，`GlobalExceptionHandler` 保证「失败也长这个样」。于是前端只需要写一个拦截器（`res.code !== 200` 就报错），不需要针对 4 个接口分别处理不同的错误格式。这就是**横切关注点集中处理**的价值。

### 6.4 配置外置 + profile

端口、数据库地址、SQL 脚本路径、驼峰映射全在 `application.yml`；换 MySQL 只加一个 `application-mysql.yml` 并用 profile 激活，**Java 代码零改动**。这是「约定优于配置」：框架按文件名和 key 自动生效。

### 6.5 「业务失败仍返回 HTTP 200」的取舍（★ 重点）

严格 RESTful 做法应该用 HTTP 404 表示资源不存在。本项目没这么做，是因为**前端和 Mock.js 早已约定 `code` 才是判定依据**：

```js
if (res.code !== 200) return Promise.reject(new Error(res.message))
```

如果后端改返回 HTTP 404，axios 会直接走 `error` 回调，`res.message` 就取不到了，前端要重写。所以这是**为兼容既有契约做的务实妥协**，不是 Java 后端的通用规范。真实新项目更常见的是「HTTP 状态码 + 统一错误体」两者都用。

### 6.6 校验做了两遍，事务划在写操作上

- 前端 `StudentForm.vue` 的 rules：即时提示，提升体验。
- 后端 `StudentRequest` 的注解 + `@Valid`：**安全边界**，防绕过页面。
- `@Transactional` 全部加在 Service 的写方法上，读方法不加（读不需要事务）。虽然本例单条 SQL 看不出效果，但边界位置是对的。

### 6.7 这个教学项目「省略」了什么（帮你建立正确预期）

知道边界，比误以为「后端就是这样」更重要。真实项目通常还会有：

- 用户登录 / 鉴权（Spring Security、JWT）、权限控制
- 数据库连接池调优、Flyway/Liquibase 管理表结构版本
- 日志规范、链路追踪、统一错误码字典、接口文档（Swagger / OpenAPI）
- 分页插件（PageHelper）、MyBatis-Plus、DTO 映射工具（MapStruct）
- Service 更细的拆分、缓存、参数限流
- LIKE 通配符转义、SQL 注入之外的 XSS/越权防护
- Docker / CI / 部署配置

**本项目刻意把这些都拿掉了，只留下一条最干净的 CRUD 主干**——这正是它适合入门的原因。

## 7. 注解速查表（读代码时随手查）

| 注解 | 出现位置 | 白话解释 |
|---|---|---|
| `@SpringBootApplication` | 启动类 | 启动 Spring + 自动配置 + 扫描本包组件 |
| `@MapperScan` | 启动类 | 让 MyBatis 为 Mapper 接口生成代理 Bean |
| `@RestController` | Controller | 这是个 HTTP 接口类，返回值直接转 JSON |
| `@RequestMapping` | Controller 类上 | 公共 URL 前缀 |
| `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` | Controller 方法 | 匹配「HTTP 方法 + 路径」 |
| `@PathVariable` | 方法参数 | 取 URL 路径里的 `{id}` |
| `@RequestBody` | 方法参数 | 把请求体 JSON 转成对象 |
| `@Valid` | 方法参数 | 触发该对象上的校验注解 |
| `@Service` | ServiceImpl | 注册为 Bean（业务层） |
| `@Configuration` | WebConfig | 注册为配置类 |
| `@RestControllerAdvice` | GlobalExceptionHandler | 全局接管所有 Controller 的异常 |
| `@ExceptionHandler` | 处理器方法 | 声明「我处理哪种异常」 |
| `@Transactional` | Service 写方法 | 方法内数据库操作处于同一事务 |
| `@Param` | Mapper 参数 | 给参数起名，供 XML `#{名}` 使用 |
| `@NotBlank` / `@NotNull` / `@Size` / `@Min` / `@Max` / `@Pattern` | DTO 字段 | 字段校验规则 + 错误提示语 |
| `@JsonIgnoreProperties` | DTO 类 | 忽略 JSON 里多余的未知字段 |

**补充**：本项目用的是**构造器注入**，所以你看不到 `@Autowired`。它是 Spring 官方推荐的写法，好处是依赖不可变、将来替换实现也方便。

## 8. 概念小词典

| 词 | 的意思 |
|---|---|
| **Bean** | 交给 Spring 容器管理的对象实例 |
| **IoC / DI** | 对象不由你 new，由容器创建并自动塞给需要它的地方 |
| **POJO / Entity / DTO** | 只有字段和 getter/setter 的简单对象 / 对应表的对象 / 层间传输的对象 |
| **CRUD** | 增删改查（Create / Read / Update / Delete） |
| **DDL** | 建表、改表结构的 SQL（`CREATE TABLE ...`） |
| **预编译 `#{}`** | 参数用 `?` 占位，不当 SQL 拼接 → 防注入 |
| **动态 SQL** | MyBatis 的 `<if>/<where>`，按条件拼出不同 SQL |
| **ORM / 结果映射** | 把数据库「行」变成 Java「对象」 |
| **事务** | 一组数据库操作要么全成功、要么全撤销 |
| **CORS** | 浏览器允许「A 端口的页面」访问「B 端口的接口」的机制 |
| **代理 / 反向代理** | `devServer.proxy` 让前端服务器替浏览器转发请求，浏览器看似同源 |
| **profile** | 一套可切换的配置（如 `mysql`） |

## 10. 常见困惑 FAQ

**Q：全项目没有 `new StudentController()`，谁创建的对象？**
A：Spring 容器。`@SpringBootApplication` 扫描到 `@RestController` 就实例化成 Bean，并自动把构造器需要的 `StudentService` 传进来（1.5 节）。

**Q：`StudentMapper` 是接口，为什么能调用方法？**
A：MyBatis 在启动时生成了代理实现类，`@MapperScan` 把它注册成 Bean。方法体在哪？在 `StudentMapper.xml` 里，靠 `namespace + id` 绑定（1.6 节）。

**Q：数据库列是 `class_name`，为什么前端收到的是 `className`？**
A：`application.yml` 开了 `map-underscore-to-camel-case`，MyBatis 查完自动映射；`Student` 的属性叫 `className`，Jackson 序列化时就输出 `className`。三处名字必须对得上。

**Q：为什么「学生不存在」HTTP 状态还是 200？**
A：为了对齐 Mock.js 和前端拦截器的既有契约（6.5 节）。是刻意的妥协，不是通用规范。

**Q：`vue.config.js` 的代理和 `WebConfig` 的 CORS 都要配吗？**
A：默认只用代理，不产生跨域；只有把前端 `baseURL` 改成直连 `http://localhost:8081/api` 时才需要 CORS。两条路二选一。

**Q：为什么改了数据，重启后又变回那 10 条？**
A：H2 是内存库 + `spring.sql.init.mode: always`，每次启动重建表并重新执行 `data.sql`。练习时很方便，生产环境不会这么配。

**Q：`@Transactional` 在这项目里好像没用？**
A：确实看不出效果（每个写方法只有一条 SQL）。它示范的是「事务边界应划在 Service 层」这个正确习惯，多步写操作时才体现价值。

**Q：编辑时请求体里带了 id，后端为什么不用？**
A：`StudentRequest` 故意不声明 id 并忽略未知字段，`update` 只认 URL 上的 `@PathVariable id`。防止请求体里的 id 和路径不一致导致改错数据。

**Q：零基础应该先看实现还是先看接口返回？**
A：先把服务跑起来，用 curl 打一遍 4 个接口，看清返回的 JSON 形状；再读主干实现，会豁然开朗。
